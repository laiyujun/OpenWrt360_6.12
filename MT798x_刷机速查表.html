关键说明

  • FIP 是什么：构建产物 bl31-uboot.fip（含 OpenWrt U-Boot + ARM 可信固件 ATF），用来刷进 FIP 分区替换原厂 U-Boot；*-preloader.bin 是 BL2（一级引导，位于 SPI-NAND/NOR 最前端）。两者配合完成"转 OpenWrt U-Boot"。
  • 真实完整文件名：本构建产物前缀为 immortalwrt-mediatek-filogic-<device>-，固件后缀为 squashfs-sysupgrade.itb（B/C 类）或 squashfs-sysupgrade.bin / squashfs-factory.bin（A 类、eMMC 机型）；本表用 * 代表该前缀。
  • 文件名前缀含义：emmc-/nand-/ubi-/ddr3-/ddr4- 是硬件变体（闪存类型/内存规格），不是 stock/ubootmod 的区别；只有 ubootmod 分支的 FIP 文件名里 <device> 含 -ubootmod。注意 BPI-R3 Mini 的真实变体是 emmc / snand（不是 nand / u-boot.fip）。
  • 额外辅助文件（非必刷）：部分 eMMC 机型另产 *-gpt.bin（eMMC 分区表，配合 preloader 使用）；release 根目录另有通用 mt7981/mt7986-ram-ddr3/ddr4-bl2.bin 等 RAM BL2，用于 UART 救砖，不是常规刷机文件。
  • 为什么有些型号"只有 ubootmod 的 fip"：因为那 4 个 ubootmod profile 的 FIP 随 profile 名带 -ubootmod 后缀，而其 -stock 兄弟（A 类）不产 FIP，所以看不到 -stock 的 fip——这是预期行为。
  • 为什么"大部分都有 fip"：B 类 14 个设备本就是 OpenWrt U-Boot 路线（源码里无 stock 变体），都产出 *-设备名-bl31-uboot.fip。
  • 原厂 U-Boot 能否直接用 ubootmod 镜像 / 反之：不能。分区表不同，混用 = 变砖。A 类与 C 类的同机型两套镜像按你机器当前跑的是哪种 U-Boot 来选。
  • 刷引导件前：务必备份原厂 BL2/FIP 分区（nanddump / mtd read），并查机型专属 wiki 的偏移与命令。secure boot 机型勿刷非签名 FIP。
